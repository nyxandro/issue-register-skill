# Issue Register

Issue Register это скилл для Claude Code, Codex, OpenCode, Cursor и других агентов, которые
понимают Agent Skills. Он сверяет реестр открытых проблем проекта (ошибки, технический долг,
открытые вопросы и решения владельца) с текущим кодом, тестами и серверами. Убирает закрытое,
оставляет то, что осталось, раскладывает пункты по видам работы, упорядочивает по влиянию на
продукт и формулирует каждый как задачу.

## Зачем

В каждом проекте, где работает агент, появляется документ с открытыми проблемами, и каждая
длинная сессия ломает его одинаково.

- Агент дописывает вместо того, чтобы переписать.
- Ставит пометку "сделано" вместо того, чтобы убрать пункт.
- Создаёт новые файлы рядом со старыми, пока никто уже не знает, какой из них актуален.

Скилл держит один реестр, сверенный с проектом, в котором только то, что осталось сделать.

## Установка

| Агент | Команда |
|---|---|
| Claude Code, как плагин | `/plugin install issue-register --marketplace nyxandro/skills` |
| Claude Code, Codex, OpenCode, Cursor и другие | `npx skills add nyxandro/issue-register-skill` |
| Любой агент, вручную | Скачайте [архив `.skill` последнего выпуска](https://github.com/nyxandro/issue-register-skill/releases/latest/download/issue-register.skill) и распакуйте в папку скиллов агента |

Выберите один способ. Если поставить двумя, Claude Code загрузит скилл дважды.

  `issue-register/`. Скилл это один файл `SKILL.md`, без скриптов и сборки.

## Как пользоваться

Формулировка запроса задаёт, насколько глубоко идёт агент.

| Вы просите | Агент |
|---|---|
| *Этот документ устарел или актуален? Что тут осталось открытым?* | Проверяет каждый пункт и отчитывается, ничего не правя |
| *Вычисти его и запиши, что ещё нужно сделать.* | Пересматривает весь реестр |
| *Добавь этот баг в реестр отдельным пунктом.* | Добавляет одну запись в нужное место и больше ничего |
| *Объедини эти два файла в один.* | Сводит пересекающиеся файлы в тот, с которым вы работаете |

Если непонятно, нужны ли правки, агент оценивает и задаёт один вопрос.

## Как работает

1. Работает в существующем реестре и никогда не создаёт новый файл. Если несколько файлов
   пересекаются, сводит их в тот, которым вы пользуетесь, остальные удаляет и пишет об этом в
   отчёте. История остаётся в git.
2. Проверяет каждый пункт по проекту, а не по документу. Строка кода, тест, миграция, конфиг,
   версия на сервере (только чтение) или закрытая задача. Закрыть пункт может только
   доказательство. Пункт, который сейчас проверить нельзя, остаётся с точной пометкой, что и где
   проверить.
3. Убирает закрытые и устаревшие пункты. Никаких пометок "сделано", никакого раздела "история",
   ничего "на всякий случай". Статусы заменяются на "проверено в такую дату, вот доказательство"
   или "проверить, что и где".
4. Раскладывает пункты по видам работы. Готовые инженерные задачи, записи, которые сначала надо
   подтвердить в коде, решения владельца, которые агент никогда не берёт на себя, живые проверки
   на проде и наследие, которое нельзя удалять, пока не проверены сохранённые данные.
5. Упорядочивает пункты по влиянию на пользователей, данные, деньги и лимиты, с причиной в одну
   строку на блок, формулирует каждый как задачу с критерием готовности и ведёт сводную таблицу
   по темам.
6. Сверяет пункты с трекером задач, если проект его называет, но никогда не создаёт и не
   закрывает задачи.
7. Ничего не чинит. Ошибка, найденная при проверке, становится пунктом, а не правкой.

## Пример

Два пункта из выдуманного реестра, до и после. Удалённый пункт взят из реального случая.

```text
Before
  D-12  Dates in the wrong format   ✅ fixed?
  D-14  Refresh token gap           (needs re-check)

After
  Removed D-12. Verified 2026-11-06, 376 dates in 139 files checked, none affected.

  Fix the logout every 24 hours (D-14, ready engineering task)
    Users get logged out mid-session when the refresh token expires.
    Done when a session older than 24 hours survives a token refresh.
    To verify whether api/auth.ts still calls the old refresh endpoint.
```

Потом идёт отчёт. Сколько пунктов было и стало, что удалено и почему, что осталось по порядку
важности, какие пункты ждут вашего решения и что проверить не удалось.

## Версии

Текущая версия записана в поле `metadata.version` файла `issue-register/SKILL.md`, так что любая
установленная копия показывает, какая она. У каждой версии есть метка в git и
[выпуск](https://github.com/nyxandro/issue-register-skill/releases) со своим архивом.
[CHANGELOG.md](CHANGELOG.md) рассказывает, что изменилось.
